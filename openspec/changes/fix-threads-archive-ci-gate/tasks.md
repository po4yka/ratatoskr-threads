## 2. Fix the timestamp precision mismatch

- [x] 2.1 `crates/threads-archive/src/browser_capture_command.rs`: `BrowserCaptureCommand::parse` now calls `.trunc_subsecs(6)` (`chrono::SubsecRound`) on the parsed `captured_at` immediately after `.with_timezone(&Utc)`, matching the microsecond floor PostgreSQL already applies on write. No other production code path compares an in-memory `captured_at` against a persisted one for equality (verified: `browser_capture_inbox.rs::deliver` only writes and returns `capture_id`; `publishing.rs`'s `timestamp()` re-reads the row and further truncates to whole seconds for the wire, never comparing against the pre-persistence value) — the fix removes phantom precision the type should never have claimed, not a workaround for one test.
