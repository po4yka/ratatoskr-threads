## Why

`ci` / job `gate` is red at `main` (run 33092775164, commit e845a6c): `threads_command_is_deduplicated_with_capture_provenance_and_queued_operation_report` (`crates/threads-archive/tests/browser_capture_command.rs:114`) panics with `assertion left == right failed`, `left: 2026-08-27T16:23:12.854786Z`, `right: 2026-08-27T16:23:12.854786273Z`. `BrowserCaptureCommand::parse` (`crates/threads-archive/src/browser_capture_command.rs`) keeps the full nanosecond precision `WireTimestamp::to_wire()` renders, but `threads_archive.captures.captured_at` is `timestamptz` (schema.sql:325), a microsecond-resolution column; PostgreSQL silently floors the sub-microsecond remainder on write. The test compares the in-memory `captured_at` against the value read back after persistence, so it fails whenever the process clock happens to land on a non-multiple-of-1000-nanosecond instant — deterministic on Linux CI, coincidental on this macOS box (8/8 local runs passed only because none of the 8 samples produced a nonzero nanosecond remainder).

This bug first landed in commit 2e5510c and has never been visible in a completed `cargo test --workspace --locked` run: two earlier defects on the two prior commits (a clippy wildcard-import lint, then the 850-line file-size gate) failed the job before the test binary carrying this assertion ever ran, and `cargo test --workspace --locked` has no `--no-fail-fast`, so the job stopped at the first failing test binary in every run since. Fixing only this one assertion does not turn the gate green: `.github/workflows/ci.yml`'s `services:` block provisions only `postgres`, never `nats`, while three test binaries added in the same commit as the browser-capture feature (`crates/threads-archive/tests/nats_browser_capture.rs`, `services/threads-archive/tests/boot.rs`, `services/threads-archive/tests/reprocess_export.rs`) hardcode a live JetStream connection to `127.0.0.1:5422` — the address `compose.yaml` publishes locally. Without a broker in CI, `cargo test --workspace --locked` fails deterministically on the first of those three binaries the moment the timestamp assertion above stops masking it. Fixing the CI provisioning gap surfaced a second, pre-existing bug: `compose.yaml`'s own `nats` service overrides the image's default command with `["-js"]`, which replaces (not extends) the default `--config /etc/nats/nats-server.conf` the image would otherwise use — the monitor port the service's own `healthcheck` polls (`http://127.0.0.1:8222/healthz`) never starts, so that healthcheck could never have passed since the file was written.

## What Changes

- `crates/threads-archive/src/browser_capture_command.rs`: `BrowserCaptureCommand::parse` truncates the parsed `captured_at` to microsecond precision (`chrono::SubsecRound::trunc_subsecs(6)`) immediately after parsing, so the in-memory value already equals what a later read of the persisted row returns, rather than carrying phantom sub-microsecond precision the column can never hold. This is a domain-boundary fix, not a test-only patch: nothing in production code currently re-compares a persisted `captured_at` against the in-memory value for equality, but the mismatch is a landmine for the next consumer that does (replay-safety checks, future dedup logic), and the type should not claim precision the wire contract cannot deliver.
- `.github/workflows/ci.yml`: adds an explicit `docker run ... nats:2-alpine@sha256:d4ac35882ac65aff236cd65b9d3fa4d24332c681e1a85f94eedccd3cdd65b1da -js -m 8222` step (a GitHub Actions `services:` entry cannot be given a command, so JetStream cannot be enabled that way on the stock image), published on `127.0.0.1:5422` to match `compose.yaml` and the three test binaries' hardcoded default, with a `curl`-polled `/healthz` readiness wait before the build/test steps run. This is the same pattern already used by `ratatoskr-platform`, `ratatoskr-extractor`, `ratatoskr-x`, `ratatoskr-instagram`, and `ratatoskr-telegram`.
- `compose.yaml`: adds `-m 8222` to the `nats` service's `command`, fixing its `healthcheck` (previously always failing/unhealthy, silently, because nothing in this repository's compose stack depends on that health status).
- `DEVELOPMENT.md`: documents the NATS broker alongside PostgreSQL in the "Current validation" section, so the prose matches what the gate now provisions.

## Capabilities

No contract, schema, or wire-visible behaviour changes; `skip_specs: true`. `captured_at()` is never placed in the queued operation report or any other outbound payload before persistence — the truncation only removes precision the storage layer already discarded on every prior run, so no downstream consumer observes a different value than it already did. The CI and `compose.yaml` changes are pure infrastructure/provisioning.

## Impact

- `crates/threads-archive/src/browser_capture_command.rs` (production code, one function).
- `.github/workflows/ci.yml`, `compose.yaml`, `DEVELOPMENT.md` (CI provisioning and local-dev parity; no `cargo` command list changes, so the `ci.yml`/`DEVELOPMENT.md` drift guard is untouched).
- No schema, wire type, or generated artifact changes.
